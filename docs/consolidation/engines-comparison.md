# Python engines comparison

## Scope and method

Canonical subsystem: `backend/app/engines/` (33 Python files). Variant code is organized under `gaia_genesis/`, so path checks compare each module path relative to that package root with the canonical engine root. Equivalence checks use Python AST structure and declared class/function names; they do not prove runtime or engineering correctness.

All Python files under the three historical `gaia_genesis/` package trees are listed. The package includes some non-engine support code; `api_v1/`, `core/`, and root `main.py` entries are explicitly marked out of scope for merging into the engines subsystem.

The two requested variant folders contain these engine-package copies:

- `A-main` - `thepetrolumen/thepetrolumen_new/backend/gaia_genesis` (39 `.py` files)
- `A-embedded-copy` - `thepetrolumen/thepetrolumen_new/possible feature calculation/THE-petrolumen-cafa105c2124580e244b9abca798a163d4588449/gaia_genesis` (89 `.py` files)
- `B` - `THE-petrolumen-cafa105c2124580e244b9abca798a163d4588449 (2)/THE-petrolumen-cafa105c2124580e244b9abca798a163d4588449/gaia_genesis` (90 `.py` files)

The embedded copy in variant A is included because it is a separate `gaia_genesis/` tree inside that folder. It shares 89 relative module paths with variant B, but those shared files are not byte-identical; treat them as divergent snapshots, not redundant files. API-name similarity is only a triage signal. A merge candidate is absent at the same relative path and worth reviewing, not safe to copy wholesale.
